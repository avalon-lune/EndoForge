# EndoForge 第三阶段：双器械与物理剪切

本版本提供键鼠控制的夹钳与剪刀，用于训练薄组织片上的抓持、牵拉、剪开和释放。UE 工程和程序内部仍保留 `LapTrainer` 名称。当前是工程训练原型，材料和接触参数未经真实组织标定；适用范围与剪切离散方式见 `Source/docs/PHASE3.md`。

## 启动

1. 完整解压压缩包到可写的本地目录，保留 `EndoForge` 内的所有文件夹。
2. 双击 `StartTrainer.cmd`，等待本地物理服务和 UE 窗口出现。
3. 普通测试不需要安装 UE 编辑器、Blender、Python 或完整 SOFA SDK，也不需要真实器械。
4. 按 `F10` 或关闭游戏窗口退出。启动器随后只关闭本次创建的物理服务。

支持 Windows x64、DirectX 11。若提示缺少 Visual C++ 运行库，可运行 `Engine/Extras/Redist/en-us/vc_redist.x64.exe`。本阶段使用 `127.0.0.1:47323`，与一期和二期的端口分开；同一时间只运行一个三期实例。端口占用时启动器会报错，不会关闭其他程序。请使用 `StartTrainer.cmd` 启动，不要只双击内部游戏 EXE。

## 双器械操作逻辑

一次控制一个器械，切换时另一个器械停在已到达的位置。`C` 切换当前器械；选择夹钳时，`F` 切换持续闭合，使切换到剪刀后仍能牵住组织。选择剪刀时，`F` 可释放已闭合的夹钳；重新闭合夹钳需要先选回夹钳。屏幕状态栏会显示当前器械、夹持与剪切状态。

| 操作 | 键鼠 |
|---|---|
| 选择夹钳 / 剪刀 | `C` 切换 |
| 当前器械闭合 / 张开 | 按住 / 松开 `Space`；夹钳持续闭合开启时，松开空格不会解除该状态 |
| 夹钳持续闭合开关 | 选择夹钳时按 `F`；选择剪刀时 `F` 仅可释放已闭合的夹钳 |
| 在水平面移动当前尖端 | 按住鼠标右键拖动，或方向键；方向随相机视角变化 |
| 升高 / 降低 | `W` / `S`；滚轮亦可调节高度 |
| 沿杆身插入 / 撤出 | `T` / `G` |
| 绕杆轴旋转 | `Q` / `E` |
| 精细移动 / 快移 | `Ctrl` / `Shift` 加运动键 |
| 初始预设 / 双器械准备预设 | `1` / `2`，会复位组织 |
| 剪刀准备位置 | `3`，保留当前组织与切口 |
| 完全复位组织与器械 | `R` |
| 视角 | `Tab` 循环切换四个视角 |
| 帮助 | `H` |
| 松开器械并释放鼠标 | `Esc`；再次右键可捕获鼠标 |
| 退出 | `F10` 或关闭窗口 |

### 第一次试用

1. 按 `2` 复位薄片并让器械前往双器械准备位置，等待器械移动到位。按 `Tab` 选择便于看清自由边的视角。
2. 选择夹钳，让自由边进入钳口，再按 `F` 持续闭合。确认屏幕显示有效抓持后，使用 `Ctrl+W` 小幅抬起组织。
3. 按 `C` 切换剪刀。夹钳会保留位置和闭合状态；可按 `3` 将剪刀移至准备位置，当前组织不会复位。
4. 使用方向键及 `W/S` 让张开的刀刃接近薄片。持续按住 `Space`，直到刀刃闭合并出现剪切事件；短促点按可能尚未达到触发角度。松开空格，等待刀刃充分张开，先轻抬至离开组织，再移到下一处、下降接近并闭合，逐段推进切口。闭合着横向拖动不会开始新的剪切动作。
5. 切换回夹钳继续轻微牵拉，观察剪开位置的分离与剩余连接；按 `F` 解除持续闭合，释放组织。
6. 按 `R` 恢复完整薄片。复位也会清除切口与器械闭合状态。

剪切由刀刃与组织接近以及闭合动作共同触发。单纯移动张开的剪刀不会剪开；在空中闭合也不应增加剪切计数。当前剪切受物理网格分辨率限制，切口边界不会具有任意精度。出现保护状态时松开操作键并按 `R` 复位，保留日志用于反馈。若状态变为不健康，模型会冻结在最后接受的位置，此时钳口不会继续执行张开动画。

## 物理和视觉范围

剪开会改变组织的承力连接，切后剩余组织和分离部分继续参加物理更新。组织位置、切口状态和器械实际位置通过同一状态消息同步给 UE。当前专注薄训练片，未实现通用三维实质器官切割、缝合、打结、电凝、出血、真实器械力反馈或临床有效性验证。

薄片尺寸为 120 × 80 × 1.5 mm，总质量为 14.4 g。初始物理网格有 850 个节点、2,304 个四面体和 1,696 个外表面三角形，由间距 5 mm 的 425 点中面网格沿厚度展开而成，后侧一排的上下层节点固定。切口沿选中的网格边贯穿薄片厚度，分开对应材料节点，保留四面体、材料质量和切前运动状态，并生成切口侧壁；切后节点数和外表面三角形数会增加。剪刀内侧必须实际接触组织，才会在当前闭合动作中收集有限刀刃区域内的候选边。候选边中点到实际接触点的距离限于 3.6 mm；刀刃闭合区域另受长度和宽度范围限制。刀刃闭合到触发角度后，会从本次实际接触支持的候选边中选择一条不分叉的网格路径，每次闭合最多执行一批剪切，需充分张开才能再次剪切。

这种方法会真实改变承力连接，但切口有明显的 5 mm 网格分辨率限制，不能精确复现刀锋轨迹。界面中的剪切次数统计成功剪切批次，切口长度统计已断开网格边的原始长度，均不等于鼠标移动距离。

当前采用 SOFA 大变形 `TetrahedronFEMForceField` 与摩擦接触，杨氏模量为 25 kPa，泊松比为 0.35，密度为 1,000 kg/m³。每次成功的物理更新推进 1/30 秒模拟时间；若候选步未通过数值检查，会恢复上一步并改用两个、再四个更小子步重试。渲染独立，实际更新频率受求解耗时影响，不能由模拟步长推断为稳定 30 Hz。接触求解采用数值正则化，当前参数未经实物标定。显示使用物理体积网格的外表面，包括真实切口侧壁。重力关闭，分离组织可因弹性和接触继续运动，不模拟重力下落。

本阶段没有组织自碰撞、完整杆身碰撞、器械之间的碰撞或连续线段碰撞检测；组织与钳口均使用三角形和点碰撞模型。屏幕中的 N 数值是最后一次成功子步的模型接触载荷，不是实际器械测量、净反作用力、整个更新周期平均值或组织损伤阈值。物理场景重建失败时保留上一份完整状态；普通求解也检查数值、单元质量和接触载荷。全部子步方案均失败时会回退、清除抓持与闭合命令并计入保护次数；若数值或单元质量不合格则冻结模型，需按 `R` 复位。常规自动验收要求保护次数为零，自适应重试次数另行记录。测得耗时只代表当前电脑和测试场景，不保证硬实时运行；较慢的物理步会增加操作响应延迟。

细化器械模型、组织材质和切口显示用于辅助观察。显示细节并不增加物理网格分辨率，也不构成真实组织材料证据。二期厚组织垫交付文件保留在原目录，本阶段使用独立测试包。

## 自动验收与反馈

包内 `Verification/` 保留交付所用的原生物理、真实 TCP、UE 输入测试、截图、会话 CSV、构建日志及程序哈希。具体判定与实测指标以原始 JSON 为准。

完整截图按操作顺序命名为 `phase3_01_ready.png` 至 `phase3_07_reset.png`。以下两张来自本包独立程序的输入验收：

![剪切后的组织分离状态](Verification/phase3_05_separation.png)

截图只能用于观察外观；是否断开承力连接、质量是否保留、复位是否恢复完整网格，要结合 `Verification/phase3-physics-test-results.json` 与 `Verification/phase3-input-test.json` 阅读。`Verification/验证记录.md` 汇总该包的实测求解耗时和证据位置。

可在 PowerShell 中重复 UE 输入验收：

```powershell
& .\StartTrainer.ps1 -LapPhase3Test -LapAutoExit -LapCaptureDir 'C:\Temp\EndoForgePhase3'
```

该测试向 UE PlayerController 注入软件输入，再检查实际物理状态。它不代替使用实体键鼠的手感测试或医疗人员验收。`-LapAutoDemo`、`-LapKeyTest`、`-LapPhase2Test` 不属于第三阶段验收入口。

新的运行日志位于 `Logs/`。会话 CSV 在游戏的 `Saved/Sessions/` 下生成；准确路径可在游戏日志搜索 `LAP_SESSION telemetry=`。反馈时请说明使用的视角、器械、按键和预设，附上日志、会话 CSV 与截图。

## 源码、依赖与文件完整性

- `Source/Physics/`：物理源码、构建与测试脚本、依赖版本及哈希。
- `Source/LapTrainer/`：UE 工程、资产、配置和源码。
- `Source/Scripts/`：本阶段装配、测试和压缩包验证脚本。
- `Source/docs/PHASE3.md`：英文技术说明和限制。
- `Source/Dependencies/sofa-v26.06.00-source.zip`：所用 SOFA 版本的对应源码。
- `Licenses/`、`Physics/licenses/`：第三方许可及声明。
- `package-manifest.json`：分发文件大小与 SHA-256；运行后新增的日志和会话不在清单中。

重建需将上述源码恢复到仓库的 `Physics/`、`Prototype/LapTrainer/`、`Scripts/` 和 `docs/` 目录结构，并安装 UE 5.7.4 与对应 C++ 工具链。SDK 下载继续放在仓库内 `ThirdParty/`。公开仓库为 https://github.com/avalon-lune/EndoForge 。本次本地交付不等于已经发布新的 GitHub Release。
